## 1. CRITICAL CRASHES — FIX THESE FIRST

### [FIX] Annotation TDZ crash — `currentAnnotations` before initialization

**File:** `annotation.js`

**Symptom:** Runtime crash on annotation open:
`Cannot access 'currentAnnotations' before initialization`

**Cause:** `resizeCanvas()` is called at module init time. It internally
calls `redraw()`. `redraw()` references `currentAnnotations` — but
`currentAnnotations` is declared with `const` *after* `resizeCanvas` in
the file. This is a temporal dead zone violation.

**Fix:** Move the declaration of `currentAnnotations` (and any other
annotation state arrays: `currentTexts`, undo stack, etc.) to the **top
of the module**, before any function that references them is called.

```js
// CORRECT — state declared first, before any function calls
const currentAnnotations = [];
const currentTexts = [];
const undoStack = [];

function resizeCanvas() { ... }   // references currentAnnotations safely
function redraw() { ... }
```

### [FIX] HTTP 400 on post / comment / note / annotation creation

**Files:** `api.js` (root fix), `post.js`, `anb.js`, `annotation.js`

**Symptom:** Creating any content returns HTTP 400 with message:
`"authorId and authorName are required"`

**Cause:** Individual call sites were not including `authorId` and
`authorName` in request bodies. Some sites also read comment/note text
from a stale captured variable instead of the form field at submit time.

**Fix — apply universally in `api.js`:**

The fetch wrapper must automatically attach `authorId` and `authorName`
from `sessionState` to every POST and PATCH request body. Individual
call sites must not be responsible for this.

```js
// api.js — POST wrapper pattern
function post(path, body = {}) {
  return fetch(`/api/postings${path}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      authorId: sessionState.userId,
      authorName: sessionState.userName,
      ...body
    })
  });
}
// Apply same pattern to PATCH wrapper
```

**Fix — comment textarea:**
At submit time, read `.value` directly from the textarea DOM element.
Never use a variable that captured the value at an earlier point.

```js
// CORRECT
const text = document.getElementById('comment-input').value.trim();
if (!text) return;
await api.postComment(postId, { text });

// WRONG — stale variable
await api.postComment(postId, { text: capturedText });
```

### [FIX] Pinboard cards not selectable / sticky notes not draggable

**File:** `pinboard.js`

**Symptom:** Cards render but clicking or dragging them does nothing.

**Cause:** No hit testing or drag lifecycle was implemented.

**Fix — implement the full interaction loop without exception:**

```
User Event → Translate Coordinates → Hit Test → Mutate State → redraw()
```

Every interaction ends in `redraw()`. Nothing else updates the display.

**Coordinate translation (run every event through this):**

```js
function toCanvasCoords(screenX, screenY) {
  const rect = canvas.getBoundingClientRect();
  return {
    x: (screenX - rect.left - transform.x) / transform.scale,
    y: (screenY - rect.top - transform.y) / transform.scale
  };
}
```

**Hit testing (reverse render order = topmost first):**

```js
function hitTest(canvasX, canvasY) {
  for (let i = cards.length - 1; i >= 0; i--) {
    const c = cards[i];
    if (canvasX >= c.x && canvasX <= c.x + c.width &&
        canvasY >= c.y && canvasY <= c.y + c.height) return c;
  }
  return null;
}
```

**Drag lifecycle — track across three events:**

- `mousedown`: hit test → if card hit, set `dragTarget`, record offset
  and `mouseDownPos`, set `movedFlag = false`; if empty canvas, begin pan
- `mousemove`: if `dragTarget`, update card position, set `movedFlag = true` if moved > 3px, call `redraw()`; if panning, update transform
- `mouseup`: if `movedFlag = false`, treat as click (select toggle in
  edit mode); if `movedFlag = true`, drag complete; clear `dragTarget`

The 3px threshold (`movedFlag`) is mandatory — without it every drag
also fires a selection toggle.

Mirror all mouse events with touch equivalents using `e.touches[0]`.
Always call `e.preventDefault()` on touch events inside the canvas.

## 2. BROKEN FLOWS — FIX THESE SECOND

### [FIX] Annotation text tool not working

**File:** `annotation.js`

**Symptom:** Clicking Text tool, then clicking on the canvas, does
nothing. No input appears, no text is placed.

**Fix — implement click-to-place text:**

1. When Text tool is active, listen for `click` on the annotation canvas
1. On click, translate the click coordinates to canvas-space (percentage)
1. Create a small floating `<input>` element positioned at the click
   coordinates (absolute, positioned relative to the canvas container)
1. Style it as a sticky-note: slight paper-colored background,
   auto-expanding width, no fixed size, subtle fold-corner triangle
1. On `Enter` or `blur`: commit — store `{ x, y, text }` in
   `currentTexts[]`, render the text on the canvas, remove the input
1. On `Escape`: cancel — remove the input, place nothing

Text items in `currentTexts[]` are discrete undoable units (same as
strokes for Draw).

### [FIX] Annotation apply — preview field written incorrectly

**File:** `annotation.js`, `anb.js`

**Symptom:** ANB Notes tab shows blank or missing previews for text
annotations.

**Fix — two parts:**

**Part 1 — at Apply time:** When saving a text annotation, write both:

- `texts: currentTexts` — the full array of `{ x, y, text }` objects
- `text: currentTexts.map(t => t.text).join(' ')` — a flat preview string

Both fields must be present on the annotation object sent to the API.

**Part 2 — in ANB rendering:** When building the preview string for
display, read from both paths:

```js
const preview = ann.texts?.[0]?.text || ann.text || '(drawing)';
```

### [FIX] Pinboard sticky notes — cannot create new ones

**File:** `pinboard.js`

**Symptom:** The “+ Sticky” button either does nothing or uses
`window.prompt()` which is blocked or returns null.

**Fix:**

- Remove any `prompt()` usage for sticky note creation

- The form dismisses after creation

The `stickyNote` type must be preserved on round-trip to/from the API.
Sticky notes participate in: multi-select, drag, group, context mode,
and filter system — same as post pins.

## 3. NEW BEHAVIOUR — ADD THESE

### [ADD] New Post modal — structured creation form

**File:** `post.js`, `feed.js`

v3.1 created a blank post directly. v3.2 requires a structured modal
before the editor opens. The modal collects:

- Title (required — validate before submitting)
- Category
- Tags (comma-separated)

The purpose is to orient the writer before they open the document.
After modal submission:

1. POST to `/posts` with title, category, tags, authorId, authorName
1. Prepend new card to feed via `Feed.prependPost()`
1. Open the new post immediately in D2 (editor)

The modal must not be a browser dialog. It is a styled dark-card modal
with blur backdrop, consistent with the rest of the aesthetic system.

## 4. PINBOARD — ADDITIONAL SPEC CLARIFICATIONS

These were vague in v3.1 and are now explicit:

### [CHANGE] redraw() structure — order is mandatory

```js
function redraw() {
  ctx.clearRect(0, 0, canvas.width, canvas.height);
  ctx.save();
  ctx.translate(transform.x, transform.y);
  ctx.scale(transform.scale, transform.scale);

  drawConnections();    // bezier lines — drawn first, behind cards
  drawGroupBrackets();  // rounded rect borders behind group members
  drawCards();          // all cards
  drawSelectionUI();    // rings, glows, context highlights — topmost

  ctx.restore();
}
```

Nothing is drawn outside of `redraw()`. Every state mutation ends with
a `redraw()` call.

### [CHANGE] Pinboard state — add missing fields

```js
// Add these to the state object if not present
selectedIds[]  // IDs of currently selected cards (edit mode)
focusedId      // ID of card in context/focus mode (browse mode)
boardDirty     // boolean — true if unsaved changes exist
```

### [CHANGE] Edit mode exit — save only if dirty

On edit mode exit: if `boardDirty === true`, save board state to
`PUT /api/postings/pinboard/:workspace`, then clear selection and
reset `boardDirty = false`.

### [CHANGE] Group creation — action bar source

The floating action bar for group creation slides up from the **canvas
bottom**, not from a panel. It appears when 2+ cards are selected in
edit mode. It contains:

- “N cards selected” label
- Group name input
- Create Group button
- Unlink Group button (only if all selected cards share a `groupId`)
- Clear button
